# 인쇄용 카드 디자인 룰

이 문서는 인쇄용 카드 PDF를 만들 때 생존자 카드와 이벤트 카드가 같은 인쇄 언어를 공유하도록 정리한 기본 스타일입니다. 카드 인쇄 기본값은 슬리브 여유를 위해 `60mm x 90mm`로 둡니다.

## 인쇄 규격

- 용지: A4 세로, 300dpi 기준으로 생성한다.
- 카드 크기: `60mm x 90mm` 고정.
- 카드 간격: `0`. 같은 행/열의 카드가 서로 맞닿도록 배치한다.
- 배치: A4 한 장에 3열 x 3행까지 배치한다.
- 안전 여백: 테스트 출력 기준으로 카드 내부 안전 여백을 두지 않는다.
- 커팅라인: 카드 외곽선과 같은 위치에 점선 커팅라인을 표시한다.
- 카드 배경: 흑백 출력을 기본으로 하며, 색상 정보는 명도 차이와 라인/바/아이콘 형태로도 구분 가능해야 한다.

## 그리기 순서

1. 카드 배경을 먼저 그린다.
2. 헤더/하단 바처럼 카드 끝까지 닿는 요소를 그린다.
3. 본문 텍스트, 조건, 보상, 아이콘을 그린다.
4. 카드 외곽 라운딩 테두리를 가장 마지막에 그린다.
5. 바를 사용할 경우 바는 카드 외곽선 뒤에 깔리도록 그리고, 외곽선이 바 위에 올라오게 한다.

## 타이포그래피

- 최소 폰트 크기: `7.5px`.
- 설명 기본 폰트: `9px`.
- 헤더1/일반 제목: `13px`.
- 헤더3/점수·목표값 등 큰 숫자: `26px`.
- 컨셉 설명: `7.5px`, 생존자 카드에서는 기울임을 사용할 수 있다.
- 텍스트가 넘칠 경우 말줄임표로 자르지 말고, 가능한 범위에서 폰트를 줄이되 `7.5px` 아래로 내리지 않는다.
- 줄 간격은 글자 간격보다 좁아 보이지 않게 유지한다. 설명문은 기본적으로 폰트 크기 대비 여유 있는 행간을 둔다.
- 제목은 짧고 명확하게, 본문은 2~5줄 안에서 읽히도록 줄인다.

## 박스와 여백

- 라운딩 박스 내부 최소 마진은 `9px`로 둔다.
- 기능 설명 박스는 3줄까지 기본 높이를 유지하고, 4줄 이상이면 하단을 고정한 채 위쪽으로 확장한다.
- 카드 내부 정보는 카드 끝에 너무 붙지 않게 하되, 인쇄 테스트 기준 안전 여백은 별도로 두지 않는다.
- 인쇄 스크립트에서 `px` 단위 디자인 값을 사용할 때는 300dpi 이미지 픽셀로 직접 쓰지 않고 `CSS = DPI / 96`을 곱해 변환한다. 예: `14px` 마진은 `round(14 * CSS)`로 계산한다.
- 박스는 정보 묶음이 필요할 때만 사용한다. 단순한 라벨/수치에는 불필요한 네모 박스를 두르지 않는다.

## 마진 준수 검증 방법

카드 외곽 마진(`CARD_MARGIN`)을 헬퍼 함수에 파라미터로 넘기는 것만으로는 마진 준수를 보장할 수 없다. 헬퍼 함수 내부에서 해당 값을 기준으로 박스 패딩(`pad_y` 등)을 더해 실제 드로잉 좌표가 마진 경계를 벗어날 수 있기 때문이다.

- 마진 검증은 **호출부 파라미터가 아니라 실제로 그려지는 좌표**를 기준으로 한다.
- 헬퍼 함수가 경계값(`condition_bottom`, `ix + margin` 등)을 파라미터로 받을 때, 함수 내부에서 해당 값을 **앵커(기준점)**로 사용하는지 확인한다. 앵커가 박스의 외곽(상단·하단·좌·우)이어야 하며, 패딩이 경계 바깥쪽이 아닌 안쪽으로만 확장되어야 한다.
- 예: `y = condition_bottom`을 받은 함수가 `box_bottom = y + pad_y`로 그리면 마진 침범이다. `box_bottom = y`, `text_y = y - pad_y`로 앵커를 경계에 고정해야 한다.
- 헬퍼 함수의 위치 파라미터는 **베이스라인(내부 기준점)** 과 **경계(하드 바운더리)** 중 무엇인지 명확히 정의한다. 베이스라인 방식은 양방향으로 박스가 확장되므로 경계값을 넘기면 마진을 침범한다. 이 프로젝트의 드로잉 헬퍼는 **경계 방식**을 원칙으로 한다: `bottom`은 박스 하단, `top`은 박스 상단을 의미하며 패딩은 경계 안쪽으로만 확장한다.

## 빌드 이벤트 카드 레이아웃 참조

이벤트 카드는 별도 문서 [event-card-print-layout.md](./event-card-print-layout.md)의 빌드 기준 배치 규칙을 우선 참고한다. 요약하면 상단 헤더에는 보상/특수 제목, 중앙에는 이름과 설명 또는 아티팩트 이미지, 하단에는 조건·주사위 목표·실패 패널티를 배치한다.

## 이벤트 카드 구성

- 상단: 획득 가능한 보상 또는 특수 카드 제목을 가장 먼저 보여준다.
- 본문: 이벤트명과 설명을 중앙 정렬로 배치한다. 열쇠/단서 같은 특수 카드는 큰 아이콘과 짧은 컨셉 문구를 우선한다.
- 하단: 해결 조건, 주사위 목표값, 필수 타입, 실패 패널티를 배치한다.
- 조건과 보상은 데이터상 분리해서 관리하고, 카드에서도 서로 다른 위치/위계로 표현한다.
- 타입 조건은 미니 태그로 표현한다. 같은 타입이 여러 명 필요하면 숫자 축약 대신 태그를 필요한 수만큼 반복한다.
- 주사위 이벤트는 큰 목표값을 사용해 난이도를 빠르게 읽게 한다.
- 열쇠가 필요한 보물/아이템 이벤트는 조건 영역에 열쇠를 명확히 포함한다.

## 생존자 카드 구성

- 상단: 점수와 생존자 이름을 먼저 읽히게 한다.
- 중앙: 얼굴 이미지 영역을 비워두거나 이미지가 들어갈 공간으로 확보한다.
- 하단: 기능 설명 박스와 컨셉 설명을 분리한다.
- 최하단 바: 타입과 비용을 묶어 표기한다.

## 아이콘 룰

- 인쇄용 PDF에서는 컬러 의존도를 낮추고 흑백에서도 구분되는 실루엣을 우선한다.
- 자원, 열쇠, 단서, 보물, 주사위, 타입은 가능한 한 반복 아이콘으로 통일한다.
- 보상 아이콘은 카드 좌상단, 이벤트 타입/성격 아이콘은 우상단에 두되 기준점과 크기를 맞춘다.
