# 멸망했는데 바쁨 — 실행과 공개 배포

## 지금 PC에서 친구들과 테스트

```sh
npm install
npm run dev -- --host 0.0.0.0
```

터미널에 표시된 Network 주소로 같은 Wi-Fi의 휴대폰·PC에서 접속합니다. 기본 주소(`/`)와 `/expedition`은 현재 프로토타입입니다. `/original`과 `/expedition-v1`은 기존 게임 호환을 위한 보관판입니다. 현재 플레이는 기본 주소를 사용합니다. 방을 만든 뒤 코드를 공유하고, 각자 이름과 지도자를 고릅니다. 모두 준비하면 방장이 시작합니다. `localhost` 주소를 다른 기기에 공유하면 안 됩니다. Network 주소에서 방을 만들면 초대 링크도 그 주소와 방의 버전을 사용합니다. 다른 버전의 방 코드로는 참가할 수 없습니다.

봇과 빠르게 확인하려면 첫 화면에서 `먼저 혼자 연습해 볼래요`를 누르세요.

## 공개 주소 만들기: Render

1. 이 프로젝트를 GitHub 저장소에 올립니다. 작업 폴더에 다른 프로젝트나 민감한 파일이 함께 있다면 이 앱만 별도 저장소로 올리세요. `node_modules`, 출력 PDF, `.env`, 로컬 방 저장 파일은 포함하지 않습니다.
2. Render에서 **New → Blueprint**를 선택하고 저장소를 연결합니다.
3. 저장소 루트의 `render.yaml`을 사용합니다. 하위 폴더에 앱이 있다면 Blueprint 파일 위치와 서비스 Root Directory를 이 앱 폴더로 지정합니다.
4. `apocalypse-tabletop`, Docker, Free 설정을 확인하고 사용자가 배포를 실행합니다.
5. 발급된 `https://…onrender.com` 주소에서 방을 만들고 친구에게 초대 링크를 보냅니다. HTTPS 주소에서는 링크 복사도 지원됩니다.

공개 배포는 **설정 파일 준비까지 완료**되어 있습니다. 계정 연결, 저장소 업로드, 실제 서비스 생성은 아직 실행하지 않았습니다.

서버는 `0.0.0.0:$PORT`에 바인딩하고 `/api/health`를 제공하며, 동일한 서버가 보드 화면·HTTP 행동 요청·SSE 실시간 상태를 처리합니다. 정적 사이트 배포만으로는 멀티플레이가 작동하지 않습니다.

Render 무료 웹 서비스는 15분 동안 들어오는 트래픽이 없으면 중지될 수 있고, 중지·재배포 시 로컬 파일이 사라집니다. 무료 배포에서는 진행 중 방이 재시작 후 사라질 수 있습니다. [Render 무료 서비스 안내](https://render.com/docs/free)

방을 재배포 후에도 보존하려면 지속 디스크를 지원하는 호스팅에서 디스크를 연결하고 `ROOM_SAVE_PATH=/var/data/rooms.json`을 지정하세요. Render의 지속 디스크는 유료 서비스 영역이므로 자동으로 추가하지 않았습니다. [Render 배포·파일시스템 안내](https://render.com/docs/deploys)

Blueprint 스키마와 서비스 설정은 [공식 Blueprint 레퍼런스](https://render.com/docs/blueprint-spec), 포트 설정은 [공식 Web Services 안내](https://render.com/docs/web-services)를 기준으로 작성했습니다.

## 직접 호스팅 / Docker

```sh
docker build -t apocalypse-tabletop .
docker run --rm -p 5173:5173 apocalypse-tabletop
```

Node로 직접 실행할 수도 있습니다.

```sh
npm ci
npm run build
PORT=5173 npm start
```

공개 서버에서는 HTTPS 프록시를 앞에 두세요. SSE 경로 `/api/rooms/*/stream`에는 응답 버퍼링을 끄고 긴 연결을 허용해야 합니다.

## 저장과 운영 범위

- 방당 2~4명. 사람과 봇을 섞을 수 있습니다.
- 주사위·차례·자원은 서버가 판정합니다. 다른 사람 차례의 요청, 중복 요청, 오래된 상태로 보낸 요청을 거부합니다.
- 각 브라우저의 참가 토큰은 localStorage에 저장됩니다. 같은 브라우저에서 새로고침하면 같은 자리로 돌아옵니다. 브라우저 데이터를 지우거나 다른 브라우저를 사용하면 같은 자리로 자동 복귀하지 않습니다.
- 방 코드는 입장용이고 참가 토큰은 자리 소유권입니다. 참가 토큰이나 서버 저장 파일은 공유하지 마세요.
- 연결이 끊기면 진행을 보존합니다. 30초 후 방장이 그 자리에 봇을 배치할 수 있습니다. 돌아온 참가자는 `내 자리로 돌아오기`로 다시 조작합니다.
- 방장이 끊기면 30초 후 다른 참가자가 방장을 이어받을 수 있습니다.
- 기본 방 저장 위치는 OS 임시 폴더의 `apocalypse-original-rooms-v2.json`입니다. 파일 권한은 0600이며, 최근 활동이 24시간 이내인 방을 서버 시작 때 복원합니다.
- **한 서버 프로세스용 프로토타입**입니다. 같은 저장 파일을 여러 서버 프로세스에서 공유하지 마세요. 여러 인스턴스 확장 시 공유 저장소와 방별 요청 직렬화가 필요합니다.
- Docker 설정은 작성했으며, 로컬 Docker 이미지 빌드는 별도로 실행해야 합니다. Node 빌드·서버·방 동기화는 테스트했습니다.

## 검증

```sh
npm test
npm run build
```

복원 규칙의 공개·수색·파견, 위조·중복·오래된 요청, SSE 연결과 재접속을 검사합니다. 보관된 새 규칙 엔진의 100판 테스트도 포함되지만, 이는 복원 규칙의 밸런스 검증이 아닙니다. 실제 사람이 느끼는 재미와 지도자 간 승률은 별도 대면/온라인 플레이테스트가 필요합니다.
